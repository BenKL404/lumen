# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Lumen is a Linux video player inspired by PotPlayer, built with **Rust + CXX-Qt 0.7 + QML (Qt 6) + libmpv**. Status: v1.0 (whole roadmap done).

- `README.md` — setup, architecture, roadmap, known pitfalls (French).
- `FONCTIONNALITES.md` — user-facing feature list, design identity (colors, spacing, animation timings) and the v0.2 → v1.0 roadmap. Check it before implementing UI or roadmap features so the result matches the planned design.

All docs, code comments and UI strings are in French; keep that convention.

## Commands

Run from the repo root:

```bash
cargo run                      # debug build + launch
cargo run --release
cargo test                     # unit tests (pure-Rust logic of every src/bridge module)
cargo test formats_time        # single test by name
scripts/install.sh [--default]  # release build + install to ~/.local (binary, hicolor icons, lumen.desktop); PREFIX=… to test elsewhere
scripts/uninstall.sh            # removes them, strips lumen.desktop from every *mimeapps.list and restores the pre-install defaults (*.avant-lumen backups)
```

- Requires Rust ≥ 1.85, Qt 6 dev packages (base, declarative, OpenGL) and `libmpv-dev`.
- CXX-Qt needs Qt 6's `qmake`; `.cargo/config.toml` sets `QMAKE=/usr/bin/qmake6` for every cargo command.
- `--default` writes `[Default Applications]` itself instead of `xdg-mime default`: desktops read `<desktop>-mimeapps.list` (e.g. `cosmic-mimeapps.list`) before `mimeapps.list`, and `xdg-mime` only writes the latter.
- First build is slow (CXX-Qt generates and compiles a lot of C++).

## Architecture

Three layers, all wired together by `build.rs` (`cxx-qt-build`):

1. **QML UI** (`qml/`) — compiled into the QML module `com.lumen.player`, loaded from `qrc:/qt/qml/com/lumen/player/qml/Main.qml`. `Main.qml` owns the window, the `theme` design-token object (single source for colors/radius/animation duration), keyboard shortcuts, drag-and-drop, auto-hide timer and OSD. Child components receive the theme from it.
2. **Rust (CXX-Qt)** (`src/bridge/`) — application logic. `utils.rs` exposes the `Utils` QML element (`formatTime`, `fileName`); the pure-Rust functions are kept separate from the `qobject` impl so they can be unit-tested without Qt. `history.rs` exposes `History` (resume playback: position, speed, audio/sub track, sub delay, manually added sub file; SQLite via bundled `rusqlite` in `$XDG_DATA_HOME/lumen/history.db`, keyed by decoded local path, schema migrations via `PRAGMA user_version`; QML saves every 5 s, on pause, on file change and on close; `load()` fills Q_PROPERTYs that `Main.qml`'s `resume()` reads). `playlist.rs` exposes `Playlist` (editable `Items` model tracking the current file by path, with `nextIndex`/`previousIndex`; durations probed off-thread via `cpp/probe.cpp` (libavformat) and queued back with cxx-qt `Threading`; auto playlist: same-folder files sharing the series key from `series_key()` — SxxEyy / Épisode / Partie / CD… markers or last lone number — sorted with `natural_cmp`; `items` are encoded file:// URLs; `Main.qml` calls `playlist.load()` on every open and advances on `MpvVideo.eofReached`). `settings.rs` exposes `Settings` (`$XDG_CONFIG_HOME/lumen/settings.toml` via serde/toml; missing keys default, out-of-range values clamped, unreadable file → defaults; atomic write via tmp + rename). `Main.qml` applies it in `Component.onCompleted` and writes it back in `saveSettings()` on close; window width is stored without the attached playlist width. Hover thumbnails: `cpp/thumbnail.cpp` is a `QQuickAsyncImageProvider` (`image://thumbnail/<seconds>/<hex UTF-8 path>`, URL built by `Utils.thumbnailUrl`) that decodes the nearest keyframe with libavcodec + swscale in a 2-thread pool; the response is itself the `QRunnable` (no `Q_OBJECT` in .cpp files — cxx-qt-build only runs moc on declared headers). `SeekBar` quantises hover positions (~200 steps per video) and keeps the last ready image while the next one loads. Desktop integration over D-Bus (`zbus` blocking API, always off the GUI thread): `screen_guard.rs` (`ScreenGuard.setActive`) inhibits screen sleep via `org.freedesktop.ScreenSaver` (what COSMIC/KDE implement — COSMIC's portal has no Inhibit) with the XDG portal as fallback; `mpris.rs` serves `org.mpris.MediaPlayer2.lumen` (`.instance<pid>` if taken): QML pushes state with `Mpris.update()` (on change + every second for Position) and receives desktop commands through the `command(name, number, text)` signal, queued to the Qt thread via cxx-qt `Threading`. Test with `busctl --user get-property/call org.mpris.MediaPlayer2.lumen /org/mpris/MediaPlayer2 …`. Single instance (`src/single_instance.rs`, setting `single_instance`, default on): before creating the Qt app, `main.rs` checks whether `org.mpris.MediaPlayer2.lumen` is owned and, if so, forwards the argument through MPRIS `OpenUri` + `Raise` and exits. Test it inside `dbus-run-session` with `QT_QPA_PLATFORMTHEME=generic` (the portal theme stalls a private bus) so the user's own running Lumen is not affected. Keyboard shortcuts: `shortcuts.rs` holds the action ids and default keys (`DEFAULTS`) and `resolve()` (user choices beat defaults on the same key; user-vs-user conflicts and unknown ids become warnings); stored as `[raccourcis]` in settings.toml (kept last: TOML tables must follow plain keys). `Main.qml` maps ids to functions in `keyActions` and instantiates one `Shortcut` per id with `settings.keys(id)`; menus show `keyLabel(id)`. Adding an action = entry (id, French label, keys) in `DEFAULTS` + entry in `keyActions`. `ShortcutsPanel` (F1) lists them; `Settings.reloadShortcuts()` re-reads the file and bumps `shortcutsVersion`, which the QML bindings depend on; `Settings.save()` always keeps the on-disk `[raccourcis]` so hand edits made while Lumen runs are not overwritten. Online videos go through mpv's built-in ytdl hook: at startup `Main.qml` sets `script-opts=ytdl_hook-ytdl_path=` (`Utils.ytdlPath()`: `~/.local/bin/yt-dlp` first — the distro one is too old for YouTube), `ytdl-raw-options=js-runtimes=` (`Utils.jsRuntime()`: deno/node in PATH, else newest nvm node) and a 1080p `ytdl-format`. `MpvItem.loadFailed(reason)` reports `MPV_END_FILE_REASON_ERROR`. Sound: `audio.rs` builds mpv's `af` value (10-band `equalizer` lavfi filters + `dynaudnorm`), exposed as `Utils.audioFilters()`; `Main.qml`'s `sound` object applies it on change; equalizer and normalization persist in settings.toml, `audio-delay` is reset per file. `anyPopupOpen` in Main.qml lists every popup (add new panels there and in `closePopups()`). Preferences (F5, `PreferencesPanel.qml`) are data-driven: each setting is one entry of `rows` (category, label, description, control type toggle/choice/slider/text/button/keys, `get`/`set` closures over settings, playlist, image, sound) — the search filters that same list. New mpv-facing preferences are applied in `Main.qml`'s `applyPlaybackSettings()` (startup + `Connections` on settings) and saved via the panel's `changed` signal. Image filters: `shaders.rs` embeds the AMD CAS/FSR mpv shaders from `assets/shaders/` (MIT, provenance in its README) with `include_str!`, rewrites `#define SHARPENING` for the chosen strength and writes them to `$XDG_CACHE_HOME/lumen/shaders/`; `Utils.videoShaders()` returns the `glsl-shaders` value and `Utils.scalingOptions()` the scale/cscale/dscale/deband set for the upscaler mode. Offscreen tests can't compile shaders (no GL): check them headlessly with `ffmpeg -init_hw_device vulkan … -vf hwupload,libplacebo=…:custom_shader_path=…` and a PSNR against the unfiltered frame. Online subtitles: `online_subtitles.rs` (`SubtitleSearch`) talks to the OpenSubtitles REST API v1 with `ureq` off the GUI thread (API key in settings `opensubtitles_api_key`; query params sorted/lowercase or the API 301-redirects; `http_status_as_error(false)` to read its JSON error messages), computes the OpenSubtitles movie hash, and saves `<video>.<lang>.srt` next to the video (fallback `~/.local/share/lumen/subtitles`). Without a valid key only the error path can be tested. Theming: no color is hardcoded in QML — `Main.qml`'s `theme` object is filled from `Utils.palette(settings.theme, settings.accent)` (`themes.rs`: dark/light/oled palettes + JSON skins in `~/.config/lumen/skins`, token list in `TOKENS`, `onAccent` computed from accent luminance); text drawn over the video uses `theme.onVideo`. New colors must become tokens. UI size uses `QT_SCALE_FACTOR` set in `main.rs` from `ui_scale` (next launch). Extensions: `extensions.rs` lists mpv scripts in `~/.config/lumen/scripts` (header `-- Nom :` / `-- Description :`), `Main.qml` loads the enabled ones with the mpv `load-script` command (once each; disabling needs a restart) and `MpvItem.scriptMessage` forwards `script-message lumen-osd …` to the OSD. Scripts don't get key events (Lumen does not forward keys to mpv). `MpvItem.getProperty(name)` reads any mpv property on demand (used by `InfoPanel`, Tab, polled every second while visible, and by `videoAspect()`); prefer it over new Q_PROPERTYs for one-off reads. Layout: `immersive` (fullscreen or mini mode) makes the video fill the window with floating controls; mini mode lowers the minimum size, saves the previous size in `miniRestore` (what `saveSettings()` stores) and moves the window by dragging the video. `fitWindowToVideo()` runs once per file when `video.info` gets dimensions (setting `fit_window_to_video`). `History.lastPlayed()` feeds the startup « Reprendre » banner (timestamps in ms). `video.rs` and `app.rs` are plain FFI bridges to C++ helpers (`lumen_init_video()`, and `lumen_qml_loaded()` for Qt APIs `cxx-qt-lib` doesn't expose).
3. **C++ `MpvItem`** (`cpp/mpvitem.*`) — a `QQuickFramebufferObject` that renders libmpv into the Qt Quick scene. Registered manually as `MpvVideo` in module `com.lumen.video` (not via the CXX-Qt QML module). Exists only because subclassing `QQuickFramebufferObject` isn't feasible from CXX-Qt. It exposes a few observed properties (`position`, `duration`, `paused`, `volume`, `speed`, `mediaTitle`, `hasMedia`, `subDelay`, and `tracks` = mpv `track-list` converted from `mpv_node` to a QVariantList) plus a generic `command([...])` that forwards any mpv command asynchronously.

**Rule: keep the C++ layer a thin rendering/command pipe. Any feature that doesn't touch rendering goes in Rust (`src/`), not `cpp/`.** New mpv state needed in QML is either queried via `command(...)` or added as a new `mpv_observe_property` + `Q_PROPERTY` in `MpvItem`.

Window layout (`Main.qml`): frameless window with a QML `TitleBar` (drag via `startSystemMove`, edge `ResizeEdge`s via `startSystemResize`); in windowed mode the `ControlBar` sits below the video and the `PlaylistPanel` is docked right, shrinking the `stage` item; in fullscreen both float over the video and auto-hide. `AppMenu` is the shared dropdown (title-bar « Lumen ⌄ », right-click context menu, playlist « Ajouter »); the control-bar sliders button opens `ImagePanel`. Glyph icons must exist in the system fonts — check with `fc-list ":charset=<hex>"` (e.g. 📌 renders as tofu here).

`main.rs` sets `QT_QPA_PLATFORMTHEME=xdgdesktopportal` when the variable is unset or `qt5ct` (Qt5-only), so `FileDialog`/`FolderDialog` use the desktop's native picker through the XDG portal (needs `qt6-xdgdesktopportal-platformtheme`). `AppMenu` panel height is computed from its entries, not from the column, so `popup(anchor, above)` positions correctly on first open.

Logo: `assets/lumen.svg` (source of truth; shown in the title bar, not on the welcome screen; embedded via `qrc_files` at `qrc:/qt/qml/com/lumen/player/assets/lumen.svg`), PNG exports in `assets/icons/hicolor/*/apps/lumen.png` (regenerate with `ffmpeg -width N -height N -i assets/lumen.svg …`). `lumen_init_app()` sets the desktop file name/Wayland app id to `lumen`.

`lumen <file|folder>` opens a file (or a whole folder as the playlist) at startup. For visual checks without screen capture: `LUMEN_SNAPSHOT=out.png [LUMEN_SNAPSHOT_DELAY=ms] cargo run -- video.mkv` saves the window image then closes the window (a normal close: position and settings are saved, as with ✕) (set `XDG_DATA_HOME` and `XDG_CONFIG_HOME` to temp dirs to keep the real history and settings untouched). Always put `single_instance = false` in the temp config: otherwise, if the user has Lumen open, the test process forwards to it via MPRIS (raising their window) and exits immediately. Prefer `QT_QPA_PLATFORM=offscreen` for UI-only checks: an on-screen window steals keyboard focus from the user (their keystrokes trigger Lumen shortcuts); offscreen has no GL, so no video frame. `MpvItem` queues `loadFile` until the GL render context exists, otherwise mpv starts without video output; if GL never comes up (2 s, e.g. `QT_QPA_PLATFORM=offscreen`) it loads anyway with `vid=no`, so offscreen snapshots still get duration, chapters and tracks (no picture). mpv options like `ab-loop-*`, `sub-delay`, `video-aspect-override` persist across files — reset them in `onFileLoaded`/`resume()` when they should be per file.

Adding files requires registering them in `build.rs`: QML files and Rust QObject files in the `QmlModule` (`qml_files` / `rust_files`), other CXX bridges via `.file(...)`, C++ sources in `cc_builder`.

### Threading / mpv constraints

- `lumen_init_video()` must be called in `main.rs` **before** `QGuiApplication` is created: it forces the OpenGL scene-graph backend (the renderer is GL-only) and registers `MpvVideo`.
- mpv callbacks (wakeup, redraw) arrive on mpv threads; they are marshalled to the GUI thread with `QMetaObject::invokeMethod(..., Qt::QueuedConnection)`. `MpvRenderer` runs on the Qt Quick render thread and must restore GL state (`QQuickOpenGLUtils::resetOpenGLState()`) after mpv draws.
- libmpv requires `LC_NUMERIC=C`; this is set in the `MpvItem` constructor — don't change locale elsewhere.
- `main.rs` exits with code 1 if the QML root fails to load (otherwise Qt would keep running with no window). Missing `qml6-module-*` packages only show up at this point, not at build time.
- The seek bar only sends the seek on release, to avoid flooding mpv during drags.
- Haruna (KDE) uses the same Qt Quick + libmpv approach and is a useful reference.
